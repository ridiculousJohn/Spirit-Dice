# Spirit House prototype audio

This folder contains durable recipes and the provenance of the recorded audio used by the prototype. The synthesis tools are in `Tools/Audio`. The active theme uses Halfwits & Failed Crits' CC0 dice recordings and InspectorJ's CC BY 4.0 window rain. Their source records are in `recorded-dice/source.json` and `inspectorj-rain/provenance.json`; the runtime assets include the rain attribution. Raw audition downloads and generated verification reports stay local.

The synthesis tools generate the original prototype clips, including the spirit, scoring, stage-clear, and creak effects. The provenance JSON records the recipe seed, PCM characteristics, levels, durations, and hashes. The generator uses only the Python standard library and refuses to replace a differing existing clip or provenance file. The roll and rain synthesis described below documents those original assets; the active theme selects recorded replacements.

The three roll variants combine damped bone modes, softer wood impacts, contact noise, and a final landing. Rain uses periodically filtered noise and wrapped quiet droplets, with a low room/lantern bed. The spirit cue is a short airy accent. Scoring uses a small bone tick, stage completion uses warm damped resonances, and an optional room creak is scheduled using an independent cosmetic random source at intervals of 17 to 38 seconds.

Fox gestures use `fox_whoosh_01.wav`, `fox_whoosh_02.wav`, and `fox_whoosh_03.wav`, generated by `generate_soft_whooshes.py`. The approved auditions and provenance are in `Docs/outputs/audio/fox-whoosh-v1`. These clips use softly filtered noise without tonal oscillators and have RMS levels 12 dB below the original spirit cue. `spiritClips` selects a random variation per gesture without immediate repeats, using cosmetic randomness only. The single `spirit` field is a fallback and references the first soft whoosh in this theme. The original `spirit_air.wav` remains an unused source asset.

The replaceable `SpiritAudioTheme` asset lives in `Dice-Unity/Assets/Dice/Presentation/Resources/SpiritAudio`. It provides separate ambience, effect, and creak levels. WAV files use 44.1 kHz, signed 16-bit PCM with preloaded PCM import settings; the ambient loop is stereo and the one-shots are mono. Short clips fade to silent endpoints. Circular filtering and wrapped events preserve the ambient texture across its 12-second seam.

Both generators require Python 3.9 or later and use only the standard library. Their default paths are anchored to the repository, so they can run from any working directory. Defaults write to ignored `Docs/work/audio-generated` directories. They refuse to replace differing existing files. No downloads or third-party Python packages are required.

From the repository root, generate local previews:

```text
python Tools/Audio/generate_spirit_audio.py
python Tools/Audio/generate_soft_whooshes.py
```

The first command writes the eight original synthesis WAVs and their `provenance.json` to `Docs/work/audio-generated/prototype`. The second writes three gesture WAVs, a combined audition, and their recipe manifest to `Docs/work/audio-generated/soft-whooshes`. It reads the repository's `spirit_air.wav` as its RMS reference. Override `--output` to use another local directory or `--reference` to audition against another mono, 16-bit PCM WAV.

To verify that the original synthesized runtime WAVs match the durable recipe without writing files:

```text
python Tools/Audio/generate_spirit_audio.py --output Dice-Unity/Assets/Dice/Presentation/Resources/SpiritAudio --provenance Docs/Reference/Audio/provenance.json --verify
```

The generators reproduce the synthetic cues only. Recorded dice WAVs are copied unchanged from their credited source pack. The rain provenance records its source hash and the 0.8-second equal-power tail/head crossfade applied to the runtime loop. Production recordings are already checked into `Dice-Unity`; the source links and attribution records support future replacement or processing work. Validators, verification reports, contact analyses, and downloaded audition material remain in ignored local working directories. Audition the clips and the encounter at the target device volume.

## Poltergeist clips

The merchant encounter's poltergeist uses six processed Pixabay recordings in `Dice-Unity/Assets/Dice/Presentation/Shared/SpiritAudio/Poltergeist`, assigned in `MerchantAudio.asset`. `poltergeist_giggle_01.wav` and `poltergeist_giggle_02.wav` are the `disturbanceClips` played when a die is disturbed; `poltergeist_grumble_01.wav` is the `disturbanceBlockedClips` entry played when the candle repels a disturbance. `poltergeist_ambient_giggle_01.wav` to `_03.wav` are `ambientOneShotClips`, played at random intervals during the encounter and not tied to any event. Every list selects a random clip without immediate repeats, using cosmetic randomness only.

The recordings are under the Pixabay Content License: free commercial use, no attribution required. `pixabay-poltergeist/provenance.json` records each source page, author, download hash, trim, gain, duration, and runtime clip hash. `Tools/Audio/process_poltergeist_audio.ps1` is the recipe: mono 44.1 kHz, a 170 Hz highpass and 6200 Hz lowpass, a light chorus, a 1.6-second pad feeding a seven-tap echo tail, trailing silence trimmed with a 0.35-second fade out, an 8 ms fade in, and peak normalization to -6 dBFS for the event clips or -12 dBFS for the ambient giggles. The "Child Giggle" source is trimmed to seconds 1.12-1.72 to remove room noise and crackle. The script reads the raw downloads from ignored `Docs/work/audio-downloads/poltergeist-giggles` by default, writes to ignored `Docs/work/audio-generated/poltergeist-giggles` with a JSON report, requires ffmpeg and ffprobe on PATH, and refuses to replace existing outputs. Use `-Source` and `-Output` to choose other folders; compare the report hashes with the provenance record to verify a rebuild.

Runtime checks for the integrated scene:

1. Roll repeatedly and listen for bone variation and wood landings without harsh peaks.
2. Trigger spirit, scoring, and stage completion and verify the corresponding accents.
3. Listen across the 12-second ambient boundary and through a scheduled room creak.
4. Mute during a roll, then invoke further cues: all active sources must stop and stay silent.
5. Unmute repeatedly: ambience must resume with one loop, and cue voices must remain bounded at four.
6. Disable and re-enable the component, change application focus, and pause/resume: sources must suspend and resume ambience without replaying interrupted cues.
7. Destroy the component: its child sources must disappear while the theme and clips remain loaded assets.
