01 / The run loop

The central loop is a five-die, poker-like score challenge. Each level gives a threshold, a limited number of hands and a shared pool of dice rerolls. The growing skull deck rewards particular roll patterns, positions and resource decisions. Hand upgrades increase the value of selected categories throughout the run.

Select a mode

Start a run or continue a saved run. Standard has 25 levels. Daily uses a shorter, prescribed setup.

Begin a level and roll

Load the level's threshold, hands and rerolls. Resolve skulls associated with the initial roll.

Choose dice to reroll

Spend one reroll action on the selected dice. Resolve reroll-triggered skulls. Repeat while resources and strategy permit.

Play the hand

Resolve the best hand category, upgrades and eligible skulls. Multiply Bones by Mult, apply the result to the remaining threshold, and consume a hand.

Continue or clear

If the threshold remains and hands remain, begin another hand. If the threshold is cleared, enter the reward flow. Running out of hands before clearing normally loses the run.

Build the deck and advance

Choose a skull and choose a hand upgrade between levels in the ordinary run. The next level raises the score requirement. Standard ends in victory at level 25.

State and resource boundaries

  • Hand: five dice, rerolls spent on that hand, dice changed since the initial roll, score accumulated from earlier skull activations, and once-per-hand skull eligibility.
  • Level: remaining threshold, hands, rerolls, and once-per-level eligibility. Dice rerolls are shared across hands; yellow skulls can replenish them.
  • Run: skull inventory, hand upgrade levels, level depth, selected challenges, separate skull-selection reroll currency, score and run statistics.
  • Profile: achievements, cosmetics, records and mode/challenge unlocks. A saved run can resume both play and reward-selection states.

Dice order does not change the hand category. It does change many skull conditions: endpoints, the middle die, adjacent dice and left/right sums are all part of the design. Holding the Play Hand control exposes a score preview.

Evidence: tutorial localization; RunSaveData fields; BattleHandler.CheckHand, DoPreviewCalc, PointsCountCycle; GameState values Playing, LootingSkulls and LootingHands.

02 / Scoring and hand upgrades

Bones = sum of all five dice + category Bones + upgrade Bones + skull Bones
Mult  = category Mult + upgrade Mult + skull Mult
Hand total = Bones * Mult
Remaining threshold -= Hand total

Skull Bones and Mult include effects accumulated during initial rolls/rerolls and effects earned when playing. Blue adds Bones, red adds Mult, purple adds both, and yellow restores rerolls. There is no extra universal +1 Mult on top of the category's value.

Categories start at displayed level 1 and cap at level 7: six upgrades. An upgrade adds 5 Bones and 1 Mult; Five of a Kind adds 5 Bones and 2 Mult. The best matching category supplies the hand bonus. Flush and Flush House have leftover data but are not returned by the inspected hand classifier.

Example: an unupgraded Full House of 2,2,2,5,5 scores (16 + 20) * 6 = 216 without skull effects. One upgrade changes this to (16 + 25) * 7 = 287.

03 / Reward and build economy

Skull offers

The ordinary offer has three skulls and one choice. The extracted four-step color cycle is three yellow options, then one blue/red/purple option for each of the next three offers. The generator indexes this cycle using (level depth - 1) modulo 4. The initial table entry therefore corresponds to depth 1, followed by 5, 9, 13, 17 and 21 for yellow rounds.

Endless switches to blue/red/purple offers after level 25. The inventory accumulates chosen skulls. The UI explicitly recognizes owning the same skull type in another color; color variants should not be treated as mutually exclusive types.

Offer generation filters excluded inventory items, excluded loot and the current offer. This is not an unrestricted independent draw from all 296 assets. The complete probability distribution and exclusion-history lifetime are not reconstructed here.

Upgrade offers and rerolls

Hand-upgrade selection normally offers three categories; a challenge reduces it to two. Fully upgraded categories and the two inactive categories are excluded. The generator suppresses the previous three upgrades through depth 16, the previous two through depth 21, and then removes that recent-history restriction. There is a fallback when the candidate pool becomes too small.

Rerolling a skull offer uses a separate currency from rerolling dice. Normal initialization assigns one skull reroll, with overrides for tutorial/special setup. The inspected ordinary clear path adds one skull reroll. Although a leftover-hands reward path exists in the binary, its controlling flag is set false in the inspected path; leftover hands should not be assumed to multiply this reward.

Evidence: InventoryVisualizer.GenerateLoot and TakeLoot; DatabaseObject.ReturnRandomItemOfColor; HandsSyncToUI.SelectHandsForUpgrade; ResetRunSaveDataToDefaults; PointsCountCycle. Offer depth-to-screen timing and all exceptional mode branches have not been played through end to end.

09 / Other content shipped in the build

Availability boundary: these entries are present in the installed files. They are not all confirmed as selectable gameplay in this release. The live selector exposes only Standard, Endless, Challenge and Daily.

Cursed mode

A fifth enum value, native branches and localized rules exist for Cursed mode. Its described loop gives temporary skulls for a level that add directly to Total. At the end of most levels, the player takes a cursed skull; activating cursed skulls loses Ribs. Zero Ribs loses the run. Failure to clear a level halves remaining Ribs but allows the run to continue, while clearing restores some Ribs.

The initial Ribs, regeneration amount, temporary-skull distributions and exact accessibility are not established. This should be treated as shipped design material, not a confirmed fifth playable mode.

Reroll abilities

Nine reroll ability definitions exist. Classic is the ordinary selected-dice reroll. The inspected scene uses ability value 0 (Classic); an accessible selector for the other eight was not found. Descriptions below are extracted rules, not a claim of release availability.

Chained Rerolls- Rerolling rolls the selected dice. - Every die can be rerolled only once per hand. - Start every level with two more rerolls.
Weighed Rerolls- Rerolling rolls the selected dice. - Rerolling dice never increases their value. - Start every level with one less reroll.
Cogwheel Rerolls- Rerolling increments the number of the selected die up by 1. - Rerolling a die with the number 6 turns it into 1. - Only one die can be rerolled at a time.
Reversing Rerolls- Rerolling turns the selected die upside down. - Only one die can be rerolled at a time.
Sorting Rerolls- Rerolling a die makes it swap its number with the number of the die to its right. - Rerolling the last die makes it swap its number with the first die. - Start the game with all hands upgraded once.

Inactive hand categories

Flush is described as five dice of the same parity, with a stored base of 15 Bones and 4 Mult. Flush House is a full house of the same parity, stored as 20 Bones and 7 Mult. Both have zero upgrade caps and are skipped by the inspected classifier and upgrade selection, so neither belongs in the active eight-category scoring table.

Design implications

This section is interpretation. Color separates an activation condition from its reward, allowing the same tactical preference to contribute Bones, Mult or reroll economy. Position-sensitive skulls create a second objective alongside order-independent poker categories. Yellow skulls can turn scoring conditions into additional opportunities to improve or activate a hand. Hand upgrades reward specialization while offer-history suppression encourages some breadth. Challenges remove pieces of those feedback loops without needing separate content sets.
