# Painted scene lighting prototype

October 13, 2026. The moth crossroads is the first authored use of independent lighting on painted backgrounds. Optional lighting is connected to encounter tables and journey illustrations, with shared sampled intensities for the painted scene, host tint, dice, and modifier history.

## Preview

Open `Dice > Encounter Lighting Preview` in Edit Mode to inspect the selected production entry and table. Entry/Table switches compositions; Intensity multiplier and Animate affect temporary copies. The table uses the actual dice/history renderers and any host assigned to its presentation asset. This isolated stage does not modify the open scene or player profile. The moth has no host artwork yet, and its table is not a playable encounter.

Selected runtime textures and response maps are under `Assets/Dice/Art/MothCrossroads`; the table and two lighting assets are under `Assets/Dice/Content/Presentation/MothCrossroads`. Only the chosen inputs needed by the runtime are included there. Art iterations, generation records, test helpers, and captures remain ignored local files.

Open `Dice > Lighting Preview` in Unity. The default local inputs are `Docs/work/moth-lighting-prototype/ambient-v2.png`, `illuminated.png`, and `lantern-response-v2.png`. They are experimental artwork/data maps, ignored by Git and unavailable in a fresh clone. Choose replacement PNGs in the window when those local files are absent. Loading them creates in-memory textures, not imported project assets or saved scene changes.

The default lantern intensity is 0.65 relative to the original painted contribution, with 0.12 flicker amount, speed 1, and seed 1977. Controls support steady/animated lighting, intensity, color, flicker amount and speed, seed, and comparisons against ambient and original images. Up to four lights can have independent textures and settings. Adding a light does not generate its illumination map; that must be authored for the scene.

The lantern uses distance falloff 1.6, source response 0.35, and constrained ambient. Turn off Animate when comparing fixed intensities such as 0.05, 0.1, 0.2, 0.4 and 1. Distance falloff makes distant spill fade faster at low intensity; increasing it strengthens that effect. Source response is an exponent; lowering it below 1 keeps the masked flame/glow visible longer. All three settings are independent per light. An empty response-map path preserves ordinary linear intensity scaling. The Ambient comparison shows the raw ambient file; the zero-intensity composed result also applies any enabled ambient constraints.

## Runtime contract

`SceneLightingAsset` describes an ambient base and up to four `SceneLightLayer` entries. Each layer supplies an aligned sRGB color texture, linear-composited contribution, tint, intensity, and independent flicker parameters. Normal contribution textures contain only that light's RGB contribution over black.

For the current prototype, `ContributionIncludesBase` derives a contribution by subtracting the ambient plate from a fully illuminated reference and clamping negative channels to zero. The shader adds this contribution back at the sampled intensity. This supports fast visual exploration; it is not a reconstruction of physical light transport.

`ConstrainAmbientToReference` limits the shared ambient RGB channels to the flagged full reference before any light contribution is extracted. This prevents a generated ambient plate's replacement blue highlights from adding above the original image. With one reference light, neutral tint, and intensity 1, the composition reconstructs that reference. For several full references, all use the same constrained ambient; author each reference with only its intended light contribution over a consistent ambient scene.

An optional linear `ResponseMap` packs normalized surface distance into red and a feathered source/glow mask into green. For intensity I greater than zero, the surface response is `I * min(I, 1)^(distance * DistanceFalloff)`; the source response is `I^SourceResponse`. The green mask blends these scalar responses before multiplying the RGB contribution, preserving its hue. Zero intensity is explicitly zero. These are artistic low-power response curves over fixed painted illumination and shadows, not physically reconstructed distance attenuation. Color textures are sRGB; response maps must have sRGB disabled.

`SceneLightingState` samples each light once at an absolute time. `SceneLightingMaterial` consumes that state without resampling, and also supports the original asset/time preview API. Optional intensity overrides multiply authored intensities without mutating the asset. `SceneLightFlicker` combines independently seeded smooth noise at several rates without consuming Unity's global random state.

The `Dice/Scene Lighting` shader composes in linear color space. Pass 0 supports UI stencil and rectangle clipping using the existing UI shader mechanism. Pass 1 is an explicit `Graphics.Blit` preview pass. Encounter room/table sections retain their existing UV rectangles and share one composition material. Journey backgrounds and departing panels own separate materials and sample the same absolute unscaled clock, preserving flicker continuity across transitions.

Each light also authors a receiver position, color, intensity, and range in tray-local coordinates. The dice and history shaders transform these through their respective render roots and combine up to four finite-range point lights with an authored ambient and directional key. This keeps illumination independent of the offscreen rigs' world offsets. These receiver parameters are tuned separately from the painted contribution; they are not inferred geometry. A table's host lighting position samples the same lights as a flat receiver. Individual artwork layers can opt out using `ReceiveSceneLighting`, and spectral silhouette layers retain their own tint. Tables without lighting retain their existing rendering.

## Artwork limits

The original cart image is the lantern-on reference. The revised ambient plate was generated with built-in imagegen, removing its flame and warm spill while keeping formerly warm reflections dark brown instead of replacing them with bright blue. The source and final prompt are recorded in `Docs/work/moth-lighting-prototype/ambient-v2-provenance.json`. Earlier art and captures remain preserved locally.

`Tools/Presentation/author-scene-light-response.py`, `scene-light-response-moth.json`, and `scene-light-response-moth-entry.json` are the reusable data-map authoring tool and two authored presets. They rasterize estimated distances and feathered lantern source masks without editing artwork. See `Tools/Presentation/README.md` for regeneration. Experimental output stays under ignored `Docs/work`; selected maps are imported as linear runtime assets.

The two generated images differ slightly in registration, detail, and dimensions. Normalized UVs align their framing, but subtraction can include unwanted residual differences. Production light contributions need more precise separation and review. This method varies fixed illumination and shadow patterns; it does not move shadows or reconstruct geometry. Depth/normal-based moving lights remain a separate possible extension.

## Capturing a preview

Set `DICE_LIGHTING_CAPTURE` to a nonexistent directory beneath `Docs/work`, then invoke `Dice.Editor.SceneLightingPreviewWindow.CaptureDefaultPreview` through Unity's `-executeMethod` option with graphics enabled. Keep the Unity log outside that new directory. The command writes ambient/original images, seven steady intensity samples, 120 frames at 20 fps, and a JSON record of sampled intensities and response settings. It refuses to replace an existing capture directory. Do not start a batch process against this project while its editor is open.

The earlier local video `Docs/work/moth-lighting-prototype/moth-lantern-preview.mp4` predates the response-map changes. Revised frames are in `response-capture-20261013-193810-965` beneath the same directory. Rendered frames and validation helpers/results remain ignored. Reusable runtime and editor tooling are ordinary project source.
