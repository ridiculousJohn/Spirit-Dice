## Design decisions to preserve

The mechanical baseline is Dice of Kalma, adapted into encounters with spirits. The original death/crypt setting is not the intended presentation. The first spirit is a fox host at The Last Lantern. The wider game follows an investigation through different spirits and places; future encounters need not be houses. A spirit can return in later encounters with different rules, difficulty, and story context.

Mechanics, content, progression, and presentation must remain separate. Mechanical content does not include names, icons, dialogue, art, audio, or other presentation. The engine must be usable under another skin or inside a larger game. Encounter behavior and journey sequencing must be driven by authored data, with no shared-controller branches for the fox or first encounter ID.

No project assets belong in a Resources directory. Use explicit serialized references or Addressables. Shared UI, tray, shader, font, and audio assets live under `Assets/Dice/Presentation/Shared`. The scene view references its UI theme and tray presentation; UI controls inherit their assigned theme through `SpiritUiContext`. Host and scene-lighting assets reference their shaders, and table presentation assets reference their audio themes. Keep these dependencies explicit when adding previews or authoring scripts.

Each modifier has an individual mechanical ScriptableObject and a separate presentation asset. Addressables discovers the labeled assets at startup. Preserve the per-condition implementation classes; do not reintroduce a central condition-evaluation switch or large presentation lookup dictionaries.

Encounters reuse existing modifier identities, effects, tiers and access requirements. Do not duplicate modifiers to customize encounter progression or change their tiers without discussion. Encounter reward pools and milestone unlocks reference shared modifier IDs. The moth unlocks three existing global families at stages 3, 6 and 10; those unlocks apply wherever the same modifiers are included in eligible pools. Its pools contain nine starter families and four permanent-unlock families, including the existing no-dice-rerolled family with its original unlock requirement. Player unlock state lives in the profile; modifier access is an authored eligibility rule.

Use Newtonsoft JSON for saves and profiles. New ordinary runs use fresh seeds; fixed seeds are an explicit debugging option. Save/resume preserves randomness and the pending reward choices.

The accepted visual direction is a portrait-friendly hybrid: painted room/host artwork with physical 3D rounded bone-like dice, a deep perspective tray, and a smaller 3D modifier history tray. The seated fox should feel large and present at the table. Spirit motion can use a faint spectral silhouette that anticipates the physical movement. Future hosts can be entirely ghostly animals. Charms and Hand Ranks have separate screens.

Scoring presentation is deliberately sequential. Begin with zero base, multiplier, and total. Roll-triggered modifier bonuses accumulate before playing. On Play Hand, count the raw dice into base, then apply the hand category's complete upgraded base and multiplier together, then present each matching modifier, then calculate base times multiplier and apply it to the target. Do not present a hand upgrade as a separate modifier. Show modifier feedback over its action button and slide its icon die into the history tray. Chained or post-total modifier activation must not be inferred from the reference without evidence.

## Spirit presentation authoring

Host assets list independent artwork layers in draw order. Each layer supplies a texture, pivot, reference-canvas position and size, tint, optional silhouette material, and optional deformation mesh. Mesh shapes are weighted UV displacements with a separate per-vertex opacity mask, so artwork transparency and planted contact points remain intact.

Sequences target Idle, Waiting, Arrival, or Reaction. Track curves use seconds and can replace or add position, size, rotation, opacity, or a deformation weight. Multiple Idle sequences can loop at different durations. Waiting overlays Idle; other states include Idle only when authored to do so. Arrival is sampled from normalized journey progress and does not advance independently. Reaction duration comes from the authored sequences. Optional entry-weight curves fade the difference from the captured starting pose, keeping interrupted reactions continuous. Gesture markers drive the shared spirit audio cue.

`Tools/Presentation/author-spirit-presentations.py` samples the two hosts' motion into editable Unity curves; the game does not execute it. It defaults to a new preview directory under ignored `Docs/work`. `--write-assets` explicitly reauthors both production hosts and their nine meshes. See `Tools/Presentation/README.md`. New hosts can supply different layers, sequences, durations, and sigils without adding a renderer class. The local-only `Docs/work/author-watchtower.ps1` is an obsolete initial content-generation record, not a regeneration path for the current presentation.
